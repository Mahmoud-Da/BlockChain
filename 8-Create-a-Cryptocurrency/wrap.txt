# Module 2 — Create a Cryptocurrency

## Step 1: Adding Transactions to the Blockchain

### 1. Overview

* In the previous tutorial, the required libraries were installed and imported.

* Implementation will follow **three parts**:

  1. Building the blockchain
  2. Mining the blockchain
  3. Decentralizing the blockchain

* The defining feature of a cryptocurrency compared to a general blockchain is the **ability to handle transactions**.

* **Two pillars** of this step:

  * **Transactions**: the ability to exchange cryptocurrency securely.
  * **Consensus**: ensuring all nodes share the same valid chain.

This tutorial focuses on **transactions**.

---

### 2. Concept of Transactions

* Transactions represent the transfer of cryptocurrency between parties.
* Transactions must be:

  * Recorded in a **temporary list** until a block is mined.
  * Secured and added to a block once mined.
  * Immutable once added to the blockchain.
* After inclusion in a block, the temporary list of transactions is cleared for new transactions.

---

### 3. Implementation Steps

#### a. Modify the `__init__` method

* Add a new instance variable:

  -------------------code----------------------
  self.transactions = []
  -------------------code----------------------
* This list stores pending transactions **before** they are added to a block.
* **Order is important**:

  * `self.transactions` must be initialized **before** the `create_block` method is called to create the genesis block.
  * Otherwise, `create_block` would not know where to retrieve transactions.

---

#### b. Update the `create_block` method

* Add a new key to each block dictionary:

  -------------------code----------------------
  'transactions': self.transactions
  -------------------code----------------------
* After assigning transactions to the block, reset the list:

  -------------------code----------------------
  self.transactions = []
  -------------------code----------------------
* This ensures that transactions are only included once, and each new block starts with an empty transaction list.

---

#### c. Add a new method: `add_transaction`

Purpose: define transaction format and add it to the pending list.

-------------------code----------------------
def add_transaction(self, sender, receiver, amount):
    self.transactions.append({
        'sender': sender,
        'receiver': receiver,
        'amount': amount
    })
    previous_block = self.get_previous_block()
    return previous_block['index'] + 1
-------------------code----------------------

* **Arguments**:

  * `sender`: address of sender
  * `receiver`: address of receiver
  * `amount`: number of coins transferred

* **Process**:

  * Append transaction as a dictionary with three keys: `sender`, `receiver`, `amount`.
  * Find the index of the next block (current last block index + 1).
  * Return this index so the caller knows which block will eventually contain the transaction.

---

### 4. Key Takeaways

* **Transactions are created before blocks**: they accumulate in a list and are added once a block is mined.
* The blockchain class now has:

  * A transactions list (`self.transactions`).
  * A block structure that includes transactions.
  * A method (`add_transaction`) to define and add new transactions.
* This completes the **first pillar** (transactions).
* The **next tutorials** will implement the **consensus mechanism**.

### What is Consensus?

* **Definition:** An algorithm ensuring that all nodes in the network contain the same chain at any time.
* **Importance:**

  * When a block is mined on one node, all other nodes in the decentralized network must update their chains accordingly.
  * Fundamental principle of blockchain technology.

---

Good question. Let’s simplify this step by step:

---

### What Are **Nodes**?

* In a blockchain, a **node** is just a computer (or device) that runs the blockchain software.
* Every node stores a **copy of the blockchain** and communicates with other nodes.
* When a new block is created (mined), the nodes share information so that all of them have the same version of the chain.

**Example:**
Imagine you and three friends each have a notebook.

* Every time someone writes a new transaction, all of you must update your notebooks.
* Each of you is a **node** in the network.
* Together, you keep the records consistent.

---

### Why Use a **Set** for Nodes?

When we store the list of node addresses inside our blockchain class, we have two options:

* **List:** `["127.0.0.1:5000", "127.0.0.1:5001"]`
* **Set:** `{"127.0.0.1:5000", "127.0.0.1:5001"}`

#### Benefits of a Set:

1. **No Duplicates**

   * A set automatically prevents storing the same node address twice.
   * Example: If you try to add `"127.0.0.1:5000"` two times, the set will still only keep it once.
   * With a list, you would have to manually check for duplicates.

2. **Faster Lookups**

   * Checking if a node already exists in a set is much faster than checking in a list.
   * This matters when the network grows and there are thousands of nodes.

3. **Order Doesn’t Matter**

   * Nodes are distributed worldwide and don’t need to be in any specific order.
   * A set reflects this idea better than a list, since sets are unordered collections.

---

**In short:**

* A **node** = a participant computer in the blockchain network that stores and shares the chain.
* A **set** = the best way to keep track of nodes because it avoids duplicates, is faster to check, and doesn’t assume any order.

---

### Step 1: Adding Nodes

Before implementing consensus, nodes must be handled within the blockchain.

#### Implementation in `__init__`:

* Introduce a variable for nodes:

  * `self.nodes = set()`
  * **Why a set instead of a list?**

    * No inherent order among nodes (distributed globally).
    * More efficient for computational purposes.

#### Creating the `add_node` Method:

* **Purpose:** Add a new node to the network.
* **Arguments:**

  * `self` (to access class variables).
  * `address` (URL of the node, e.g., `http://127.0.0.1:5000`).

**Process:**

1. **Parse the address** using `urlparse` (from `urllib.parse`).

   * Example result of parsing:

     * `scheme`: `http`
     * `netloc`: `127.0.0.1:5000`
   * The `netloc` (URL + port) uniquely identifies a node.
2. **Add the node to the set**:

   * `self.nodes.add(parsed_url.netloc)`

**Example:**

-------------------code----------------------
from urllib.parse import urlparse

def add_node(self, address):
    parsed_url = urlparse(address)
    self.nodes.add(parsed_url.netloc)
-------------------code----------------------

# Lecture Notes – Implementing Consensus with `replace_chain`

## 1. Introduction

* In previous tutorials, we created a **set of nodes** and the **add_node** method.
* Now, we will implement the **consensus mechanism** using a new method called **replace_chain**.
* Purpose: Ensure that every node in the network has the **longest valid chain**.
* This is an essential step before full decentralization (covered in Part 3).

---

## 2. Method: `replace_chain`

### Purpose

* Replace the chain of the current node if it is shorter than the longest valid chain in the network.
* Helps maintain consistency across all nodes.

### Arguments

* Takes only `self` because it operates on the blockchain of the specific node where it is called.

---

## 3. Variables Setup

1. **network** → `self.nodes`

   * Represents all nodes in the decentralized network.

2. **longest_chain** → `None`

   * Will eventually store the longest valid chain found in the network.

3. **max_length** → `len(self.chain)`

   * Initially set to the length of the chain in the current node.
   * Updated whenever a longer valid chain is found.

---

## 4. Looping Over Nodes

* Use a **for loop** to iterate over each node in the network.
* For each node:

  1. Send a **GET request** (`get_chain`) using the `requests` library.
  2. Verify the response is successful (`status_code == 200`).
  3. Extract:

     * **length** of the chain.
     * **chain** itself.

---

## 5. Chain Validation and Replacement

* For each node’s chain:

  * Check if `length > max_length`.
  * Check if the chain is valid (`self.is_chain_valid(chain)`).
* If both conditions are true:

  * Update `max_length` to the new length.
  * Update `longest_chain` to this chain.

---

## 6. Updating the Node’s Chain

* After the loop:

  * If `longest_chain` is not `None`:

    * Replace the current chain: `self.chain = longest_chain`.
    * Return `True` (chain was replaced).
  * Else:

    * Return `False` (no replacement was needed, current chain is already the longest).

---
-------------------code----------------------
def replace_chain(self):
        network = self.nodes
        longest_chain = None
        max_length = len(self.chain)
        for node in network:
            response = requests.get(f'http://{node}/get_chain')
            if response.status_code == 200:
                length = response.json()['length']
                chain = response.json()['chain']
                if length > max_length and self.is_chain_valid(chain):
                    max_length = length
                    longest_chain = chain
        if longest_chain:
            self.chain = longest_chain
            return True
        return False
-------------------code----------------------
## 7. Key Points

* `replace_chain` ensures **consistency** of the blockchain across the network.
* Uses **requests** library to fetch chain data from other nodes.
* Relies on **chain validity** check to avoid adopting corrupted or invalid chains.
