## Concept of Mapping

* **Definition**: A mapping is like a function, but its data is stored in an array-like structure.
* **Behavior**:

  * Takes an input variable (e.g., investor address).
  * Returns an associated value (e.g., equity).
* Unlike a function that performs an operation, a mapping directly returns stored data.

## Equity Representation

* Example:

  * $1,000 invested → $1,000 USD equity.
  * Since **1 USD = 1,000 Atcoins**, investor also has **1,000,000 Atcoins** equity.
* Need two mappings:

  1. Address → Equity in Atcoins.
  2. Address → Equity in USD.

## Syntax in Solidity

### General Structure

-------------------code----------------------
mapping(inputType => outputType) variableName;
-------------------code----------------------

### Step 1: Mapping for Atcoins

* Input: **address** (investor address).
* Output: **uint** (integer equity, no decimals).
* Variable name: `equityAtcoins`.
* Example:

-------------------code----------------------
mapping(address => uint) equityAtcoins;
-------------------code----------------------

### Step 2: Mapping for USD

* Input: **address** (investor address).
* Output: **uint**.
* Variable name: `equityUSD`.
* Example:

-------------------code----------------------
mapping(address => uint) equityUSD;
-------------------code----------------------

## Key Notes

* Use `uint` since equity is always an integer (no fractions of cents).
* Always end with a semicolon (`;`), unlike Python.
* These mappings act as lookup tables linking investors’ addresses to their respective equity.

* **Definition**: A modifier checks conditions before executing functions.
* Use case in ICO:

  * Investors can **always sell** Atcoins.
  * Investors can **only buy** if Atcoins remain available.
* Modifier ensures that purchase attempts are valid.

# Tutorial: Solidity Modifier – Checking If an Investor Can Buy AdCoins

## Objective

* Ensure that during the ICO, an investor can **only buy AdCoins if enough coins remain**.
* Use a **modifier** in Solidity to enforce this rule.

---

## What is a Modifier?

* A **modifier** is a Solidity tool that checks a condition before running a function.
* If the condition is true, the function linked to the modifier executes.
* Example use case: **Buy AdCoins function** can only run if coins are available.

---

## Steps to Create the Modifier

### 1. Define the Modifier

* Syntax:

-------------------code----------------------
modifier modifierName(parameters) {
    // condition
    _;
}
-------------------code----------------------

* For this ICO:

-------------------code----------------------
modifier canBuyAdCoins(uint usdInvested) {
    // condition goes here
    _;
}
-------------------code----------------------

* `usdInvested` → the amount of USD the investor wants to invest at a given time.

---

### 2. Condition to Check

* The goal: ensure the investor can buy the requested amount of AdCoins.

* Steps:

  1. Convert **USD invested** into **AdCoins**:

     -------------------code----------------------
     usdInvested * usd_to_adcoins
     -------------------code----------------------
  2. Add the total AdCoins **already bought** (`totalAdCoinsBought`).
  3. Ensure this sum is **less than or equal to the maximum available** (`maxAdCoins`).

* Solidity syntax using `require`:

-------------------code----------------------
require(
    (usdInvested * usd_to_adcoins + totalAdCoinsBought) <= maxAdCoins
);
-------------------code----------------------

* `require` ensures that if the condition is false, the transaction **fails immediately**.

---

### 3. Complete Modifier Code

-------------------code----------------------
modifier canBuyAdCoins(uint usdInvested) {
    require(
        (usdInvested * usd_to_adcoins + totalAdCoinsBought) <= maxAdCoins
    );
    _;
}
-------------------code----------------------

---

## Key Points

* `_` in the modifier: placeholder for the function code that uses this modifier.
* The function linked to this modifier (e.g., `buyAdCoins`) will **only execute if the condition is true**.
* This enforces **ICO limits** and prevents overselling coins.

---

This modifier is now ready to be linked to the **buy function** in the ICO contract.

In **Solidity**, the `address` type is a **special data type** that holds a **20-byte (160-bit)** value — the same size as an **Ethereum account address**.
It can represent both:

* **Externally Owned Accounts (EOAs)** — regular user wallets controlled by private keys

### Basic Forms of `address`

Solidity provides **two address types**:

| Type              | Description                                                                                                 |
| ----------------- | ----------------------------------------------------------------------------------------------------------- |
| `address`         | Basic type; can only store the address value and check balance.                                             |
| `address payable` | Extended type; can receive and send Ether via `.transfer()`, `.send()`, or `.call{value: ...}()` functions. |

---

### Example

-------------------code----------------------
pragma solidity ^0.8.0;

contract AddressExample {
    address owner;             // normal address
    address payable recipient; // can receive Ether

    constructor(address payable _recipient) {
        owner = msg.sender;      // set owner to deployer
        recipient = _recipient;  // assign recipient
    }

    function sendEther() public payable {
        require(msg.value > 0, "Must send some Ether");
        recipient.transfer(msg.value); // transfer Ether
    }

    function getOwnerBalance() public view returns (uint) {
        return owner.balance; // check balance of any address
    }
}
-------------------code----------------------

## modifier vs function
---

## **1. What is a Function**

A **function** is a block of code that performs a specific task.
You explicitly call functions to execute them.

### **Purpose**

* Execute logic (e.g., calculations, token transfers, or updates).
* Return values.
* Interact with other contracts or blockchain state.

### **Example**

-------------------code----------------------
function getBalance(address investor) public view returns (uint) {
    return equityUSD[investor];
}
-------------------code----------------------

**Explanation:**

* You call it directly (e.g., `getBalance(0x123...)`).
* It performs a task and returns a result.
* Functions can read or modify the blockchain state depending on their type (`view`, `pure`, or normal functions).

---

## **2. What is a Modifier**

A **modifier** is **not** called directly.
It is used to **alter the behavior** of functions — mainly to add conditions, checks, or reusable logic before (and optionally after) the main function body executes.

### **Purpose**

* Restrict access (for example, only owner can call).
* Validate inputs or states (for example, check if enough tokens are available).
* Reuse the same condition in multiple functions without rewriting it.

### **Syntax**

-------------------code----------------------
modifier onlyOwner() {
    require(msg.sender == owner);
    _; // This is where the rest of the function runs
}
-------------------code----------------------

### **How It’s Used**

-------------------code----------------------
function withdrawFunds() public onlyOwner {
    // Function executes only if msg.sender == owner
}
-------------------code----------------------

**Explanation:**

* The modifier runs its code first.
* When Solidity reaches `_`, it executes the main function body.
* If the modifier’s condition fails, the function stops.

---

## **3. Key Differences**

| Feature                   | **Function**                            | **Modifier**                                                        |
| ------------------------- | --------------------------------------- | ------------------------------------------------------------------- |
| **Purpose**               | Executes main logic.                    | Adds pre-/post-conditions or access control to functions.           |
| **Called Directly?**      | Yes                                     | No — only attached to functions.                                    |
| **Can Return Values?**    | Yes                                     | No (it modifies behavior, not return data).                         |
| **Uses `_` placeholder?** | No                                      | Yes — `_` indicates where the function body executes.               |
| **Typical Use Cases**     | Calculations, transfers, state updates. | Access control (`onlyOwner`), validation (`canBuyAdCoins`), limits. |

---

## **4. Example Comparison**

### Using a Modifier

-------------------code----------------------
modifier canBuyAdCoins(uint usdInvested) {
    require(usdInvested * usd_to_hadcoins + total_hadcoins_bought <= max_hadcoins);
    _;
}

function buyCoins(address investor, uint usdInvested) public canBuyAdCoins(usdInvested) {
    uint hadcoinsBought = usdInvested * usd_to_hadcoins;
    equityAtcoins[investor] += hadcoinsBought;
    total_hadcoins_bought += hadcoinsBought;
}
-------------------code----------------------

### Without a Modifier (Using a Function Instead)

-------------------code----------------------
function buyCoins(address investor, uint usdInvested) public {
    require(usdInvested * usd_to_hadcoins + total_hadcoins_bought <= max_hadcoins);
    uint hadcoinsBought = usdInvested * usd_to_hadcoins;
    equityAtcoins[investor] += hadcoinsBought;
    total_hadcoins_bought += hadcoinsBought;
}
-------------------code----------------------

**Both achieve the same goal**, but:

* Using a **modifier** makes the code **cleaner and reusable**.
* If multiple functions need the same check, the modifier prevents repetition.

---

## **5. Summary**

| Aspect       | Function                    | Modifier                                      |
| ------------ | --------------------------- | --------------------------------------------- |
| Main Role    | Execute logic               | Enforce conditions before/after function runs |
| Invocation   | Called directly             | Attached to a function                        |
| Reusability  | Limited                     | High — can be reused by many functions        |
| Contains `_` | No                          | Yes (marks function execution point)          |
| Example Use  | `buyCoins()`, `sellCoins()` | `onlyOwner`, `canBuyAdCoins`                  |

function sellAdCoins(address investor, uint adCoinsSold) external {
    // Update equity in AdCoins for the investor by subtracting sold coins
    equityAtcoins[investor] -= adCoinsSold;

    // Update equity in USD for the investor
    equityUSD[investor] = equityAtcoins[investor] / usd_to_hadcoins;

    // Update total AdCoins bought by all investors
    total_hadcoins_bought -= adCoinsSold;
}
