* **Public variables**: Accessible by anyone (inside and outside the contract).
* **Private variables**: Accessible only within the contract.
* ICOs require **transparency**, so key values are public.

---

### 1. Maximum Number of Hadcoins

* Represents the total supply of hadcoins available for sale.
* Public variable because an ICO is public like an IPO.
* Data type: `uint` (unsigned integer, cannot be negative).

* Example declaration:

  -------------------code----------------------

  uint public max_hadcoins = 1000000;
  -------------------code----------------------

* Value initialized to **1,000,000** (the total supply).

---

### 2. Conversion Rate (USD to Hadcoins)

* Defines how many hadcoins equal 1 USD.
* Example value: **1 USD = 1000 hadcoins**.
* Public variable for transparency.
* Example declaration:

  -------------------code----------------------

  uint public usd_to_hadcoins = 1000;
  -------------------code----------------------


---

### 3. Total Hadcoins Bought

* Tracks how many hadcoins have been purchased by investors during the ICO.
* Starts at **0**, since no tokens are bought at the beginning.
* Public variable for transparency.
* Example declaration:

  -------------------code----------------------

  uint public total_hadcoins_bought = 0;
  -------------------code----------------------


---

## Summary of Variables

1. `max_hadcoins = 1000000` → total supply.
2. `usd_to_hadcoins = 1000` → conversion rate.
3. `total_hadcoins_bought = 0` → counter that updates during sales.

# Lecture Notes: ICO Contract Mappings in Solidity

## Recap from Previous Tutorial

* Introduced public variables accessible by anyone (inside and outside the contract).
* Next step: create mappings to track investor equity in **Atcoins** and **USD**.

## Concept of Mapping

* **Definition**: A mapping is like a function, but its data is stored in an array-like structure.
* **Behavior**:

  * Takes an input variable (e.g., investor address).
  * Returns an associated value (e.g., equity).
* Unlike a function that performs an operation, a mapping directly returns stored data.

## Equity Representation

* Example:

  * $1,000 invested → $1,000 USD equity.
  * Since **1 USD = 1,000 Atcoins**, investor also has **1,000,000 Atcoins** equity.
* Need two mappings:

  1. Address → Equity in Atcoins.
  2. Address → Equity in USD.

## Syntax in Solidity

### General Structure

-------------------code----------------------
mapping(inputType => outputType) variableName;
-------------------code----------------------

### Step 1: Mapping for Atcoins

* Input: **address** (investor address).
* Output: **uint** (integer equity, no decimals).
* Variable name: `equityAtcoins`.
* Example:

-------------------code----------------------
mapping(address => uint) equityAtcoins;
-------------------code----------------------

### Step 2: Mapping for USD

* Input: **address** (investor address).
* Output: **uint**.
* Variable name: `equityUSD`.
* Example:

-------------------code----------------------
mapping(address => uint) equityUSD;
-------------------code----------------------

## Key Notes

* Use `uint` since equity is always an integer (no fractions of cents).
* Always end with a semicolon (`;`), unlike Python.
* These mappings act as lookup tables linking investors’ addresses to their respective equity.

## Next Step: Modifiers

* **Definition**: A modifier checks conditions before executing functions.
* Use case in ICO:

  * Investors can **always sell** Atcoins.
  * Investors can **only buy** if Atcoins remain available.
* Modifier ensures that purchase attempts are valid.

### What is a mapping in Solidity?
---

### Mapping = “Label → Box”

* Imagine **every investor has a box**.
* The **label on the box** is their **address** (like their ID).
* Inside the box is **how many coins or dollars they have**.

So:

* `mapping(address => uint) equityAtcoins;`

  * Means: “for each address, store how many Atcoins they have.”
* `mapping(address => uint) equityUSD;`

  * Means: “for each address, store how much USD they have invested.”

**Example in words:**

* Address `0x123` → 1000 Atcoins, 1 USD
* Address `0x456` → 500 Atcoins, 0.5 USD

You don’t have to search anywhere—just **look at the box with the label** to see the value.

# Tutorial: Solidity Modifier – Checking If an Investor Can Buy AdCoins

## Objective

* Ensure that during the ICO, an investor can **only buy AdCoins if enough coins remain**.
* Use a **modifier** in Solidity to enforce this rule.

---

## What is a Modifier?

* A **modifier** is a Solidity tool that checks a condition before running a function.
* If the condition is true, the function linked to the modifier executes.
* Example use case: **Buy AdCoins function** can only run if coins are available.

---

## Steps to Create the Modifier

### 1. Define the Modifier

* Syntax:

-------------------code----------------------
modifier modifierName(parameters) {
    // condition
    _;
}
-------------------code----------------------

* For this ICO:

-------------------code----------------------
modifier canBuyAdCoins(uint usdInvested) {
    // condition goes here
    _;
}
-------------------code----------------------

* `usdInvested` → the amount of USD the investor wants to invest at a given time.

---

### 2. Condition to Check

* The goal: ensure the investor can buy the requested amount of AdCoins.

* Steps:

  1. Convert **USD invested** into **AdCoins**:

     -------------------code----------------------
     usdInvested * usd_to_adcoins
     -------------------code----------------------
  2. Add the total AdCoins **already bought** (`totalAdCoinsBought`).
  3. Ensure this sum is **less than or equal to the maximum available** (`maxAdCoins`).

* Solidity syntax using `require`:

-------------------code----------------------
require(
    (usdInvested * usd_to_adcoins + totalAdCoinsBought) <= maxAdCoins
);
-------------------code----------------------

* `require` ensures that if the condition is false, the transaction **fails immediately**.

---

### 3. Complete Modifier Code

-------------------code----------------------
modifier canBuyAdCoins(uint usdInvested) {
    require(
        (usdInvested * usd_to_adcoins + totalAdCoinsBought) <= maxAdCoins
    );
    _;
}
-------------------code----------------------

---

## Key Points

* `_` in the modifier: placeholder for the function code that uses this modifier.
* The function linked to this modifier (e.g., `buyAdCoins`) will **only execute if the condition is true**.
* This enforces **ICO limits** and prevents overselling coins.

---

This modifier is now ready to be linked to the **buy function** in the ICO contract.

## Lecture Notes: Creating Functions in Solidity

### 1. Introduction

* The tutorial focuses on creating the **first functions in Solidity**.
* The goal is to create two functions that will:

  * Retrieve the **equity in alt coins** of an investor.
  * Retrieve the **equity in USD** of an investor.

---

### 2. Function Basics in Solidity

* To define a function in Solidity, use the keyword `function`.
* Each function must have:

  1. A **name**.
  2. **Input parameters** (arguments).
  3. A **return type** that specifies the output.
  4. Optionally, a **visibility modifier** (such as `external`, `public`, etc.).

---

### 3. Creating the `equityInAltCoins` Function

#### Step 1: Function Declaration

-------------------code----------------------
function equityInAltCoins(address investor) external constant returns (uint) {
    return equityAltCoins[investor];
}
-------------------code----------------------

#### Explanation

* `function` – keyword to declare a function.
* `equityInAltCoins` – name of the function.
* `(address investor)` – input parameter:

  * `address` is the data type.
  * `investor` is the variable name.
* `external constant` – indicates that:

  * The function is accessible from outside the contract.
  * The function does not modify the blockchain state.
* `returns (uint)` – specifies that the function returns an unsigned integer.

#### Purpose

* Takes the investor’s address as input.
* Uses the previously defined **mapping** (`equityAltCoins`) to return the equity value associated with that address.
* The mapping links investor addresses to their alt coin equity values.

---

### 4. Why Create This Function Instead of Using the Mapping Directly

* The function serves as an **interface tool** for external interaction (e.g., through MyEtherWallet).
* It allows users to call this function directly from a wallet or frontend interface.
* Even though it retrieves data that could be accessed directly, it’s necessary for user-friendly interaction with contracts.

---

### 5. Creating the `equityInUSD` Function

#### Step 1: Duplicate and Modify

* Copy the previous function and adjust names accordingly.

-------------------code----------------------
function equityInUSD(address investor) external constant returns (uint) {
    return equityUSD[investor];
}
-------------------code----------------------

#### Explanation

* Same logic as before.
* Uses a different mapping: `equityUSD`.

### 6. Key Solidity Concepts Introduced

| Concept      | Description                                                                                      |
| ------------ | ------------------------------------------------------------------------------------------------ |
| **address**  | A 20-byte identifier representing an account (user or contract).                                 |
| **external** | Function visibility modifier; callable only from outside the contract.                           |
| **constant** | Indicates that the function does not alter the blockchain state.                                 |
| **uint**     | Unsigned integer type, used for non-negative numeric values.                                     |

In **Solidity**, the `address` type is a **special data type** that holds a **20-byte (160-bit)** value — the same size as an **Ethereum account address**.
It can represent both:

* **Externally Owned Accounts (EOAs)** — regular user wallets controlled by private keys
* **Contract Accounts** — addresses of deployed smart contracts

---

### Basic Forms of `address`

Solidity provides **two address types**:

| Type              | Description                                                                                                 |
| ----------------- | ----------------------------------------------------------------------------------------------------------- |
| `address`         | Basic type; can only store the address value and check balance.                                             |
| `address payable` | Extended type; can receive and send Ether via `.transfer()`, `.send()`, or `.call{value: ...}()` functions. |

---

### Example

-------------------code----------------------
pragma solidity ^0.8.0;

contract AddressExample {
    address owner;             // normal address
    address payable recipient; // can receive Ether

    constructor(address payable _recipient) {
        owner = msg.sender;      // set owner to deployer
        recipient = _recipient;  // assign recipient
    }

    function sendEther() public payable {
        require(msg.value > 0, "Must send some Ether");
        recipient.transfer(msg.value); // transfer Ether
    }

    function getOwnerBalance() public view returns (uint) {
        return owner.balance; // check balance of any address
    }
}
-------------------code----------------------

---

### Common Address Members and Methods

| Member / Method          | Description                                               | Example                                             |
| ------------------------ | --------------------------------------------------------- | --------------------------------------------------- |
| `.balance`               | Returns the amount of Wei held by the address.            | `uint bal = addr.balance;`                          |
| `.transfer(uint amount)` | Sends Ether (reverts on failure).                         | `addr.transfer(1 ether);`                           |
| `.send(uint amount)`     | Sends Ether (returns bool, does not revert).              | `bool sent = addr.send(1 ether);`                   |
| `.call{value: x}("")`    | Low-level call to send Ether and optionally execute code. | `(bool success, ) = addr.call{value: 1 ether}("");` |

---

### Type Conversions

You can **cast** between the two types when needed:

-------------------code----------------------
address addr = 0x123...;
address payable payAddr = payable(addr);
-------------------code----------------------

---

### Summary

| Feature                                                  | `address` | `address payable` |
| -------------------------------------------------------- | --------- | ----------------- |
| Holds 20-byte Ethereum address                           | ●         | ●                 |
| Can receive Ether                                        | X         | ●                 |
| Can send Ether using `.transfer()`, `.send()`, `.call()` | X         | ●                 |
| Has `.balance` property                                  | ●         | ●                 |
